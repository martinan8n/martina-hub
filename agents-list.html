Agents list

Today the Agents list is just a table of names and dates — you have to open an agent to learn anything about it. Four Linear tickets ask for more visibility right in the list; this workstream figures out how they fit together rather than bolting each on separately.

🧩 Problem

You can't tell from the list whether an agent last ran successfully, never ran at all, or is just an empty shell someone created and forgot about. Every one of those questions requires opening the agent. AGENT-798 (duplicate in the row menu, mirroring the Workflows pattern) already shipped — the rest are open.

🧪 Hypothesis

Surfacing last-run time (AGENT-901), a visual flag for empty/throwaway agents (AGENT-906), a Description item in the row menu (AGENT-948), and a failed-run indicator (AGENT-979, backlog) lets people triage their agents from the list alone. Grouping the two "needs attention" signals (failed runs, empty agents) into a small summary above the list — rather than making people scan every row for them — is the one piece none of the four tickets asked for on their own.

Source: Linear — AGENT-798, AGENT-901, AGENT-906, AGENT-948, AGENT-979

Needs attention lists agents by name, not just a count — failures can stack up across several agents, so a bare "1 agent failed" undersells it once there are three. Added Awaiting approval here too (not one of the four tickets — her own addition, see open question 4). Last run (AGENT-901) now also carries the Failed (AGENT-979) and Awaiting states, both dot-coloured with neutral text per the hub's status convention. Empty agents (AGENT-906) dropped the pill badge and instead render the whole row in light gray — quieter than an alert, since an unused agent isn't urgent the way a failure or a pending approval is. Row menu adds Description (AGENT-948) next to the already-shipped Duplicate (AGENT-798).

Open questions

  1. 1The row menu's exact order (Open, Rename, Description, Duplicate, Delete) is a guess — AGENT-948 says Description should match Workflows' menu, but this was built from the ticket text alone, not a screenshot of that real menu. Confirm the real order and wording before this ships.
  2. 2Needs attention items are static, not clickable here. Should clicking one filter/scroll the list below to that agent? Feels like the obvious next step.
  3. 3Empty (AGENT-906) and Failed (AGENT-979) are treated as mutually exclusive — an agent with no runs can't also have a failed run. Worth confirming that holds for however "empty" actually gets defined (never run vs. never configured aren't necessarily the same thing).
  4. 4Awaiting approval isn't one of the four tickets — added because approval-gated runs are a real "needs attention" case (see the approval-mode work in Goal-based tasks). Needs its own ticket if this is worth building alongside the other four, and someone should confirm what actually counts as "awaiting" for an agent versus a workflow run.
  5. 5Empty agents no longer appear in Needs attention, only as a grayed-out row in the list itself — a deliberate call that "unused" is lower-urgency than a failure or a pending approval. Flag if that's wrong and it should still be counted/listed above.
